# Experiment Design

## Failure Scenarios

- F0: no failure.
- F1: request is lost before gateway receive.
- F2: timeout before downstream dispatch.
- F3: response loss after successful side effect.
- F4: delayed response causing retry.
- F5: duplicate agent invocation.
- F6: concurrent duplicate invocation with fanout 2, 5, or 10.
- F7: gateway/orchestrator abort before downstream call.
- F8: downstream effect commits while ledger remains `EXECUTING`, then execution becomes ambiguous.
- F9: effect confirmation is persisted but final replayable result is interrupted.
- F10: temporary ledger unavailability hook reserved for database fault runs.
- F11: retry storm generated by the agent simulator.
- F12: downstream ambiguity without query capability.

Fault decisions are deterministic from `seed`, `operation_id`, `scenario`, and `hook`.

## Metrics

The runner writes raw `events.csv`, `operations.csv`, `effects.csv`, and `summary.json`. Summary metrics include DER, EOER, LER, RSR, RAF, DAF, RRR, UAR, latency percentiles, and throughput.

Failed and unresolved operations remain in the denominator. The runner does not remove outliers or fabricate missing results.

## Ground Truth

Business services insert rows into `observer.observer_effects` after actual business effects. Runtime services have no read access to this table. Gateway and orchestrator have no observer privileges.

Analysis reads observer rows only after a run to compute `effect_count`.

## Config Schema

Configs are YAML and include:

- `experiment.id`
- `workload.type`, `operations`, `concurrency`, `warmup_operations`
- `architecture.variant`, `downstream_capability`
- `failure.scenario`, `probability`, `seed`
- `retry.max_attempts`, `backoff`
- `timeouts.client_ms`, `downstream_ms`
- `output` flags

## Pilot

Pilot configs in `configs/pilot` cover V0, V2, V4, V5 and F0, F3, F6, F8 using C0/C1/C2 where representative.
